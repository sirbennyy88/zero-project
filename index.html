      BOD 26-04 · the deadlines behind the due dates

      On 10 June 2026 CISA replaced BOD 22-01's flat "14 days for anything new in KEV" with a four-variable risk matrix — internet exposure, KEV status, exploit-automation potential, technical impact — producing tiered remediation windows. Its stated rationale is AI-compressed disclosure-to-weaponisation timelines. Compliance literature published before mid-2026 still describes 22-01 as current; it is not.

        How to read this

        No one publishes a "zero-days per week" series. The two closest public, weekly-resolvable datasets are used here. CISA KEV counts vulnerabilities with confirmed in-the-wild exploitation; it includes old CVEs newly seen exploited, so the same-year split is the better proxy for fresh zero-days. It is US-government-curated and lags vendor confirmation by days. Google TIG's yearly count is the other widely cited number and is shown in the five-year row.

        Mythos findings are not exploits. The ledger counts vulnerabilities the model found and Anthropic disclosed under its 90-day policy — most were never exploited by anyone. The discovery spike in the week of 30 Mar 2026 reflects a pre-launch scanning run over 1,000+ open-source projects, and the ledger covers only Anthropic's own open-source work, not the 10,000+ partner findings (Microsoft, Apple, Cisco, Mozilla's 271 Firefox bugs, Cloudflare's 2,000, etc.), which are reported only as aggregates.

        Vendor CVE counts come from cve.org records grouped by the assigning CNA, as processed by Epoch AI's Cyber Vulnerabilities explorer; severity is the CNA's own CVSS rating with ADP fallback. They measure what vendors published, which mixes Mythos findings, other AI scanners (OpenAI's GPT-5.5/5.6-Cyber and Daybreak, Microsoft's MDASH), changed CVE-assignment policies (the Linux kernel became its own CNA in Feb 2024), and ordinary bug-finding.

        Product classes are assigned by keyword match against the KEV entry's vendor and product fields, first match wins. It is a coarse mapping — "Cisco IOS XE" is an edge appliance here while "Cisco Webex" falls to enterprise app — and it exists to make the category chart legible, not to be an asset taxonomy.

        Time to exploit joins KEV's dateAdded to the CVE's publication date from cvelistV5 / NVD. A negative or zero value means the CVE was published on or after the day CISA added it, which happens when exploitation is confirmed before the record goes public; those entries are kept and visible in the distribution.

        NVD enrichment changed on 15 April 2026. NVD now fully enriches only KEV, federal and EO 14028 critical-software CVEs, and reclassified roughly 29,000 backlogged pre-March-2026 records as "Not Scheduled". Severity and CVSS coverage outside that scope is systematically thinner from that date on — it affects the fresh-vs-old ratio and vendor severity splits, not the KEV counts themselves.

        Ecosystem and framework counts are GitHub-reviewed advisories by publication month and advisories published by each repository. Projects that disclose outside GitHub show as zero there. Patch Tuesday counts come straight from Microsoft's CVRF feed, so they can differ by a few from Tenable's write-ups (which also exclude some third-party CVEs).

        Framework mapping is editorial: the clause list per metric was compiled against each framework's published text, and paraphrased where the primary text is paywalled (ISO 27002, SOC 2 points of focus, CSA AICM detail pages). Draft documents are marked Draft and should not be cited as binding.

        Week boundaries are ISO Mondays. The latest week is partial until the next Monday refresh.

        API

        The same data behind this page is mirrored into a Cloudflare D1 database and exposed as a small read-only JSON API, for anyone who wants a single week, a single CVE, or a search without downloading the full JSON/CSV export. All responses are JSON with CORS enabled (Access-Control-Allow-Origin: *) and cached at the edge for an hour; rate limiting relies on Cloudflare Workers' free-tier defaults. This is a defensive, best-effort API — treat the static zeroweek-data.json / zeroweek-data.csv exports as the source of truth.

        Base URL: https://zero-project-api.benito-1d7.workers.dev

        EndpointWhat it returns
        GET /api/weeks?from=&to=Weekly KEV totals in a date range
        GET /api/week/{YYYY-MM-DD}KEV entries added that ISO week, joined with EPSS / exploit / SSVC signals
        GET /api/cve/{id}One CVE across KEV, EPSS, exploit signals, and SSVC
        GET /api/vendors?week=Vendor (CNA) high/critical counts for a week
        GET /api/products/{id}Monthly severity counts for a watchlist product
        GET /api/search?q=Search CVE ID / vendor / product / name (limit 50)
        GET /api/statsRow-count totals and last refresh timestamp

        Examples:
